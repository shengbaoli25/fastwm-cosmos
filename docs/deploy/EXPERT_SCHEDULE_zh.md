# Joint8 真机部署：编译与完整采样图

2026-10-23。本次将离线专家采样评测使用的 `ExpertScheduleRunner` 正式接入部署适配器，新增 `joint_expert_schedule` 后端。支持网页中的 Video/Force/Action = 16/16/16 和 4/4/16；不修改权重、训练代码、采样区间、种子序列、相机预处理或动作反归一化。

## 实现与原路径的区别

原 `joint_multirate` 的 `mode=cuda_graph` 分别捕获三个专家的前向，Python 调度各采样轮，分支调用需要复制输入和输出。新路径编译 Force/Action 层、缓存固定文本特征及采样时间调制，并把整个多步采样循环捕获为一个图。Video 保留原生运算，当前观测、历史和本体状态仍每次刷新；返回的张量拥有独立存储，后续回放不会覆盖上一动作块。

`joint_expert_schedule` 显式选择生效；旧配置继续使用原后端。配置中的 `sampling_profile` 不再覆盖新后端为 `joint_multirate`。网页切换采样配置会保留后端、卸载旧策略并要求重新加载，因此不会拿 16/16/16 的旧图执行 4/4/16。直接在已加载策略上修改采样配置也会被拒绝。

编译和捕获使用指定 CUDA 设备及该设备的流，在模型加载预热阶段完成；异常直接上报，不静默回退。诊断报告实际 runner、compile 状态、图的范围、采样步数以及缓存/图构建次数。网页仅在成功执行后显示“编译＋完整采样图已启用”。

## 本机启用配置

```json
{
  "inference_backend": "joint_expert_schedule",
  "sampling_profile": "4416",
  "execution_mode": "synchronous",
  "inference_optimization": {
    "compile_layers": true,
    "cuda_graph": true,
    "compile_threads": 4
  }
}
```

替换旧优化配置时需删除 `mode`；它只适用于原 `joint_multirate`。模型加载前须提供当前 Python 对应的开发头文件。本机复用此前离线环境的本地 Python 3.12 头文件，并在启动脚本加入 `CPATH`，无需修改系统 PyTorch。原运行配置、启动脚本已各保留备份。

本机仍用 cup step20000：SHA256 `34efeb39d0079848c09ca4120655ee94ae4fb1950055a73ecf096f4dff560da6`；设备 GB10，BF16，Torch 2.9.1+cu130。服务地址为 `http://127.0.0.1:8765`。

- 部署适配器、设置 API、运行时、模型导出和采样缓存相关的第一轮测试：78 passed、4 subtests passed。
- 新增小型随机模型 CUDA 回归：16/16/16 和 4/4/16 均启用 Force/Action 编译及完整采样图，两项通过；与旧多速率实现的 BF16 比较使用 atol=rtol=0.04，同时验证输入刷新、图复用和旧输出不被覆盖。该容差是小模型的实现回归标准，不是物理动作误差标准。
- 网页测试：13 项通过，包括区分准备中、分支图、编译完整图和错误状态。

## 操作者的真机验证

1. 刷新网页，确认 step20000、4/4/16、同步模式，以及“编译＋完整采样图已启用”。连接硬件并等待既有就绪检查通过，再由操作者启动；不改变夹爪参数或时序保护。
2. 使用相同场景和动作块长度，记录真实输入的图像处理、模型阶段及整体推理延迟；排除加载预热，对已接受推理统计 P50/P95，同时保留丢弃结果和停顿记录。
3. 如对照 16/16/16，先暂停并等待在途推理结束，应用设置、重新加载，确认实际采样步数再启动。
4. 编译会改变部分浮点运算顺序。保持对动作连续性、夹爪行为和任务成功率的现场对照；性能改善不等于策略质量改善。

需要回到原路径时，停止运行后将后端改为 `joint_multirate`、优化配置改为 `{"mode":"cuda_graph"}`，保留所选采样步数，再重启服务和加载模型。
