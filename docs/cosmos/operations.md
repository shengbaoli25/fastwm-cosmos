# Ordered operation guide

Run from this repository root. Keep the original Python invocation `/inspire/hdd/project/long-range-embodied-collaborative-intelligence/ky26340/realman-fastwam/.venv/bin/python` on the current platform; do not resolve it to a system interpreter. The outer pidfd supervisor uses a system stdlib Python that actually exposes `os.pidfd_open` and `signal.pidfd_send_signal`. Its child still invokes the original `.venv/bin/python`. Test both before launch.

1. Inspect the new allocation UUID, actual visible GPUs, shared disk, Python/Torch/CUDA and available official asset files. Do not operate another experiment's output/processes. On8GPU hosts, expose4GPUs for training, preserving global64.
2. Check pinned official robot/action-cond, tokenizer and all Reason1 shard hashes. Reuse matching existing assets. A public HF download requires its normal account/license access; never substitute another checkpoint if unavailable.
3. Prepare exact dataset prompts with `scripts/cosmos/precompute_text_sdpa.py --prompts prompts.json --reason1-checkpoint /absolute/Reason1 --upstream /absolute/cosmos-predict2.5 --output /new/text --execute`. It loads the pinned NVIDIA Reason1 network with its existing SDPA path, all official parameters strictly, local processor assets, and the original 512-token right-padding and 28-layer FULL_CONCAT normalization. It needs no online model download. The original `precompute_text.py` remains available for an installed upstream extension environment. Training reads the resulting text cache, not the online Reason1 model. While text assets transfer, `stage_latents.py` can encode RGB on four GPUs into explicitly non-trainable image-only shards; final assembly still requires complete text and numeric identities.
4. Generate a bounded pilot with `scripts/cosmos/precompute_features.py` and `--limit`. Required flags are `--pixel-cache`, `--pixel-identity`, `--numeric-cache`, `--numeric-identity`, `--stats`, `--text-cache`, `--tokenizer`, `--upstream`, `--output`, `--execute`. Inspect true token shapes/finite values, camera/window alignment and encode/decode quality on actual windows before resuming all34808anchors with explicit `--resume`. This is Cosmos-specific offline encoding; original caches remain frozen.
5. Resolve `configs/task/cosmos_forcewm_4gpu_30k.yaml` into a standalone `config.yaml` with absolute paths and actual complete text/feature identities. Example: `PYTHONPATH=src python scripts/cosmos/resolve_config.py --text-cache /new/text --feature-cache /new/features --checkpoint /official/action-cond.pt --upstream /pinned/upstream --output-dir /new/formal --config-output /new/config.yaml`. The reader independently revalidates all feature hashes. Do not hand-set `???` to a guessed identity.
6. Set `COSMOS_ALLOCATION_ID` to the actual new allocation. Launch `-m fastwam.cosmos.preflight --config /new/config.yaml --output /new/probe --execute` with the exact4rank Accelerate YAML. Use `scripts/cosmos/bounded_probe.py` around its original-Python argv: `--command-json`, `--cwd`, `--output`, `--seconds`, `--deadline-unix`, `--execute`. A diagnostic deadline is newly planned for that diagnostic, not an inherited training cap. The probe retains the full30000step scheduler, performs2actualAdam updates and a full native save, then exits. This checkpoint is disposable and never the start of formal training.
7. In a fresh4rank launch, execute `scripts/cosmos/restore_probe.py --config ... --preflight /new/probe/preflight.json --preflight-outer /new/probe-watch/status.json --output /new/restore --execute`, again inside a bounded supervisor. It loads the native ZeRO checkpoint and checks exact model, per-rank Adam moments, schedule, sampler progress, CPU/CUDA RNG and Force memory RNG. Actual exits of both launches must be0with full unforced tree closure. A CPU unit test is not this step.
8. Run `scripts/cosmos/formal_run.py` with `--config`, `--preflight`, `--preflight-outer`, `--restore`, `--restore-outer`, `--supervision`, `--native-python` and explicit `--execute`. Run **in the foreground**, preferably as the platform's distributed command job when available. It verifies current source/config/resource receipts, actual six-snapshot disk estimate plus10%margin, then starts fresh official robot/action-cond + random AE/Force/control adapter. The user gave this experiment no training time cap. No `nohup`/background launcher that immediately exits a platform job is required.
9. Actual steps/loss, GPU state, storage and checkpoints determine progress. Completion requires30000steps, four complete origins, expected saved weights/fullstate and actual unforced supervisor exit. CPU pass, submitted command, elapsed time and an empty process group do not prove this. Same-data119window evaluation remains separate work after training; it must include generated Force and strict+1 labels.

**Current GPU/asset status is recorded in deployment notes, not fabricated by this guide.** Commands requiring completed feature/preflight/restore receipts intentionally fail until those artifacts truly exist. The original DeepSpeed JSON lacks `gradient_clipping`; configuration `max_grad_norm=1` does not establish engine clipping1.
